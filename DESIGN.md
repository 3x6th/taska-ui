# DESIGN.md — Taska Design System

Единый источник правды по визуалу и поведению UI Taska. Этот файл читает и человек, и агент
(Claude Code / harness) перед тем как писать или менять UI. Если код расходится с этим файлом —
прав файл; если файл устарел — сначала обнови его, потом код.

**Стек-агностично.** Значения даны как CSS-переменные и числа, чтобы лечь в CSS Modules, Tailwind
(`theme.extend`), styled-components или vanilla CSS.

---

## 1. Design principles

1. **Тихий интерфейс.** Хром бледный, контент — контрастный. Цвет несёт смысл (тип, приоритет,
   статус), а не украшает. Максимум один акцент на экране.
2. **Воздух вместо линий.** Разделяем пространством и очень слабыми бордерами (8–9% альфы),
   не жирными рамками и не тенями-«карточками».
3. **Плотность без тесноты.** Base 13px, компактные контролы (24–39px), но щедрые внешние отступы.
4. **Мгновенный отклик.** Любое действие пользователя отражается в UI сразу (оптимистично),
   сеть догоняет. Спиннер — только там, где нечего показать.
5. **Ничего лишнего.** Нет декоративных иллюстраций, эмодзи, градиентных фонов (три
   исключения: мягкое radial-свечение на экране логина, маскот-кубик на экране
   Not found — §4.18 — и маскот в каске на заглушке раздела в разработке — §4.19).
   Третье исключение добавлено решением владельца при TAS-159: разделы админки
   рисуются все сразу, включая те, у которых ещё нет ручек, и пустой раздел должен
   выглядеть как стройка, а не как поломка. Маскот — тот же персонаж, что в §4.18,
   поэтому это одна иллюстративная семья, а не вторая.
   *Известное нарушение (TAS-142): `.projects-page` несёт второй radial-градиент —
   убрать или узаконить здесь одним решением, а не молчанием.*
6. **Клавиатура — первый класс.** Всё, что кликается, доступно с клавиатуры и имеет focus-стиль.

### Hard rules (нарушать нельзя)
- Не вводить новые цвета «на глаз» — только токены ниже; новый оттенок получать через
  `color-mix(in oklab, <token> N%, transparent)`.
- Не более **двух** фоновых уровней в одной плоскости (`--surface` + `--surface-2`).
- Текст никогда не наследует цвет «случайно»: у текстовых узлов задавать `color` явно
  (`var(--fg)` / `--fg-2` / `--fg-3`).
- Entrance-анимации **не должны скрывать контент**: `fill-mode` и 0%-кадр обязаны оставлять
  элемент читаемым (см. §7).
- Группы (кнопки, чипы, аватары, тулбары) верстать `flex`/`grid` + `gap`, не margin'ами и не
  пробелами в разметке.
- Минимальная кликабельная область — 28×28 (в плотных тулбарах), целевая — 32×32.

## 2. Foundations

### 2.1 Color tokens

Тема задаётся набором переменных на корневом элементе приложения. `dark` — переопределение.

```css

  --surface:       #ffffff;
  --surface-2:     #f0f0f3;
  --surface-3:     #e9e9ee;
  --border:        rgba(22,22,32,.09);
  --border-strong: rgba(22,22,32,.15);
  --fg:            #17171b;
  --fg-2:          #56565f;
  --fg-3:          #9090a0;
  --accent:        #4f46e5;
  --accent-fg:     #ffffff;
  --shadow:        0 1px 2px rgba(20,20,40,.05), 0 4px 14px rgba(20,20,40,.05);
  --shadow-hover:  0 2px 10px rgba(20,20,40,.07);
  --shadow-pop:    0 12px 40px rgba(10,10,30,.18);

}

[data-theme="dark"] {
  --bg:            #08080b;
  --surface:       #141418;
  --surface-2:     #0f0f13;
  --surface-3:     #1c1c22;
  --border:        rgba(255,255,255,.08);
  --border-strong: rgba(255,255,255,.15);
  --fg:            #ededf1;
  --fg-2:          #9c9ca6;
  --fg-3:          #62626d;
  --accent:        color-mix(in oklab, #4f46e5, white 22%);

```

**Роли:**
| Токен | Где применять |
| --- | --- |
| `--bg` | фон рабочей области (полотно доски, страница) |
| `--surface` | карточки, панели, топбар, поповеры, модалки |
| `--surface-2` | «утопленные» плоскости: колонки доски, контейнеры сегментов, поля ввода в покое, футер модалки |
| `--surface-3` | резерв (наведение на утопленные плоскости) |
| `--border` | разделители и рамки в покое |
| `--border-strong` | рамки инпутов/кнопок, hover-рамка карточки, незалитые priority-бары |
| `--fg` | заголовки и основной текст |
| `--fg-2` | вторичный текст, лейблы, иконки в покое |
| `--fg-3` | подписи, мета, плейсхолдеры, «выключенное» |
| `--accent` | primary-кнопка, активный фильтр, статус In Progress, фокус |

**Акцент — сменный.** Поддерживаемые альтернативы (менять только `--accent`):
`#4f46e5` (default) · `#2563eb` · `#0d9488` · `#7c3aed` · `#ea580c`.

### 2.3 Typography

```css
--font-ui:   'Hanken Grotesk', system-ui, -apple-system, sans-serif;
--font-mono: 'IBM Plex Mono', ui-monospace, monospace;
```
Веса UI: 400 / 450 / 500 / 550 / 600 / 650 / 700. Mono: 400 / 500.

> `ui-monospace` в этом стеке — не рабочий фолбэк, а декларация намерения: его
> поддерживает только Safari 13.1+, в Chrome и Firefox он не реализован нигде и
> резолвится как несуществующее имя. Реально при отказе вебшрифта срабатывает
> generic `monospace` — то есть системный фиксированный шрифт пользователя
> (Consolas в Chrome/Edge на Windows, Menlo на macOS). Это и есть желаемое
> поведение, поэтому расширять стек в CSS не нужно; единственный ощутимый
> проигрыш — Firefox на Windows, где generic `monospace` даёт Courier New.
> Если стек всё же понадобится расширить — сначала сюда, потом в CSS, и ровно
> на одну запись (`… ui-monospace, Consolas, monospace`). Измерено в браузере
> 2026-08-12: `ui-monospace` и заведомо несуществующее имя дают идентичную
> ширину строки.
Базово: `font-size:13px; line-height:1.45; letter-spacing:-0.005em`.

| Роль | Размер / вес | Цвет | Трекинг |

### 2.6 Elevation

Только 4 уровня: `--shadow` (карточки, топбар) → `--shadow-hover` (hover карточки) →
`--shadow-pop` (поповер) → `--shadow-modal` (модалка). Больше уровней не вводить.

Slide-over — единственная поверхность с горизонтальной тенью, поэтому у неё отдельный
токен `--shadow-panel` (`-12px 0 40px rgba(10,10,30,.16)`, dark `rgba(0,0,0,.6)`).
Это не пятый уровень, а другая ось; в общую шкалу он не встраивается.

## 3. Motion

```css
--ease: cubic-bezier(.2,.7,.3,1);
--dur-hover: 120ms;   /* border-color, box-shadow, opacity, transform на hover */
--dur-enter: 160ms;   /* поповеры, модалки */
--dur-panel: 220ms;   /* slide-over */
```

```css
@keyframes tk-fade { from { opacity:.35 }              to { opacity:1 } }
@keyframes tk-slide{ from { transform:translateX(22px) } to { transform:translateX(0) } }
@keyframes tk-pop  { from { transform:translateY(7px); opacity:.55 } to { transform:translateY(0); opacity:1 } }
```

Правила:
- 0%-кадр **никогда** не `opacity:0` и не `display:none` — иначе контент пропадает при
  паузе анимации (offscreen-рендер, скриншот-тесты, `prefers-reduced-motion`).
- Hover-переходы: `transition: border-color .12s ease, box-shadow .12s ease, transform .12s ease`.
- Уважать `@media (prefers-reduced-motion: reduce)`. Реализовано через сами токены: в
  медиа-запросе `--dur-*` схлопываются в `1ms`, поэтому не нужен ни `!important`, ни
  борьба со специфичностью (см. §1, hard rules). Анимации с литеральной длительностью
  (`.auth-card-wrap`, `.skeleton-card`, `.avatar-loading`, `.value-skeleton`)
  перечислены там же поимённо — при добавлении новой литеральной анимации её надо
  добавить в этот список.
- Никаких bounce/spring и анимаций дольше 250ms. **Единственное исключение** —
  вход карточки логина `.auth-card-wrap` (`tk-pop` 500ms из прототипа): экран
  показывается один раз за сессию и ни с чем не конкурирует. Исключений внутри
  рабочих экранов не бывает.

## 4. Components

Спека: назначение → анатомия → размеры/токены → состояния.

### 4.1 Button
- **Primary:** `background:var(--accent); color:var(--accent-fg)`, height 32–34 (форма 39),
  radius 9, padding 0 13–16, 12.5–13.5px/600. С иконкой — `gap:6`, иконка 13.
  hover: `filter:brightness(1.06)`; active: `brightness(.96)`.
- **Secondary / outline:** `border:1px solid var(--border-strong)`, фон прозрачный,
  `color:var(--fg-2)`, hover — `background:var(--surface)` (в футере модалки) или `--surface-2`.
- **Ghost / icon:** без рамки, `color:var(--fg-2)`, размер 28–34, radius 7–9,
  hover: `background:var(--surface-2); color:var(--fg)`.
- **Destructive:** ghost + hover `color:var(--danger)`.
- **Transition button** (в карточке задачи): height 29, padding 0 12, radius 8,
  `border:1px var(--border-strong)`, 12px/550; hover: `border-color/color: var(--accent)`.
- Focus (все): `outline:2px solid var(--accent); outline-offset:2px`.
- Disabled: `opacity:.5; pointer-events:none`.

### 4.2 Segmented control
Контейнер: `display:flex; gap:2–3; padding:2–3; background:var(--surface-2); radius:8–9`.
Кнопка: height 24–30, padding 0 11–12, radius 6–7, 12–12.5px/550–600, `color:var(--fg-2)`.
Активная: `background:var(--surface); color:var(--fg); box-shadow:0 1px 2px rgba(20,20,40,.08–.12)`.
Использование: фильтр типов, Priority, Type/Priority в модалке, табы Sign in / Accept invite
(там таб — `flex:1`, height 30).

### 4.3 Input / Textarea
- Покой: height 38–42, padding 0 12, radius 9, `border:1px var(--border-strong)`,
  фон `--surface` (логин) или `--surface-2` (модалка/описание).
- Focus: `border-color:var(--accent)`; если фон был `--surface-2` → становится `--surface`.
- Placeholder: `color:var(--fg-3)`.
- Label сверху: 11.5px/550 `--fg-2`, `gap:6`.
- **Inline-edit** (summary/description в панели): рамка `transparent` в покое, на focus —
  `border-color:var(--border-strong)` + фон `--surface`; сохранять по debounce (см. §6).
- Textarea: `resize:vertical`, min-height 66–84, lh 1.5–1.55.

### 4.4 Avatar
Круг, `background: <avatar color>`, `color:#fff`, инициалы (2 символа, uppercase),
`font-size: ~40% диаметра`, weight 600. Размеры — см. §2.7.
- **Unassigned:** прозрачный фон, `border:1.5px dashed var(--border-strong)`, без текста.
- **Stack:** `margin-right:-7px`, `border:2px solid var(--surface)`, показывать до 4, далее «+N».
- **Selectable** (фильтр по исполнителю): активный — `outline:2px solid var(--accent);
  outline-offset:1.5px`; неактивные — `opacity:.85`.
- Всегда `title` / `aria-label` с полным именем.

### 4.5 Badge / Pill
- **Project key:** mono 11px/500, padding 4 8, radius 7, letter-spacing .02em,
  фон `color-mix(in oklab, <projectColor> 16%, transparent)`, текст `<projectColor>`.
- **Count pill** (в заголовке колонки): 11px/600 `--fg-3`, `background:var(--surface-2)`,
  padding 1 7, radius 20.
- **Status pill** (в панели): height 28, padding 0 12, radius 8, 12.5px/600,
  фон `color-mix(in oklab, <statusColor> 14%, transparent)`, текст `<statusColor>`.
- **Label chip** (метка задачи, TAS-169): height 20, padding 0 8, radius 20,
  11.5px/600, фон `color-mix(in oklab, <labelColor> 16%, transparent)`,
  текст `<labelColor>`. Цвет метки приходит с сервера, а не из токенов, поэтому
  задаётся инлайном; значение, не проходящее контрактный `^#[0-9A-Fa-f]{6}$`,
  заменяется на `--accent`, а не рисуется как есть. Имя метки — всегда текст:
  цвет здесь не единственный носитель смысла ровно по причине из §4.6.
  Съёмная метка несёт внутри кнопку 15×15 на `currentColor` с обязательным
  `aria-label` «Remove <name>»; длинное имя обрезается многоточием, чтобы чип
  не растягивал строку.

### 4.6 Type chip
Квадрат 14×14, `radius:4`, фон = цвет типа. **BUG — круг (`radius:50%`)**, чтобы тип читался
без цвета (важно для дальтоников). Рядом всегда текстовая метка типа (overline) или `aria-label`.

### 4.7 Priority indicator
Три бара, ширина 3, высоты 5 / 8 / 11 (снизу выровнены), radius 1, `gap:2`.
Залито `level` штук цветом приоритета, остальные — `--border-strong`.
LOW=1, MEDIUM=2, HIGH=3. Обязателен `title`/`aria-label` («High priority»).

### 4.8 Card
- **Issue card:** `background:var(--surface); border:1px var(--border); radius:11; padding:12 13;
  box-shadow:var(--shadow); cursor:grab`.
  Анатомия: [type chip · issueKey (mono) · тип (overline) · ─── · priority bars] →
  заголовок 13/500 → (опц.) превью описания 2 строки → (опц.) метки, не более
  двух рядов (`max-height:46`, дальше обрезается — полный список читается в
  панели, а дата и аватар внизу карточки не должны уезжать) →
  [дата создания · аватар исполнителя].
  hover: `border-color:var(--border-strong); box-shadow:var(--shadow-hover)`.
  dragging: `opacity:.4`.
- **Project card:** `radius:13; padding:17`, hover `border-strong` + `translateY(-2px)`.
  Анатомия: [key badge · название] → описание → [avatar stack · «N members» ─── «N issues»].

### 4.9 Board column
`width:312; radius:13; padding:11px 9px 4px; display:flex; flex-direction:column`.
Фон: `--surface-2` (вариант `subtle`, по умолчанию) или `transparent` (`plain`).
Заголовок: status dot 8px → имя 12.5/650 `--fg` → count pill → ─── → кнопка «+» (22px).
Список: `flex:1; overflow-y:auto; gap:8`.
**Drag-over:** `box-shadow: inset 0 0 0 2px var(--accent)`.
**Empty:** «Drop issues here» — 11.5px `--fg-3`, `border:1px dashed var(--border-strong)`,
radius 10, padding 18 0.

### 4.10 Slide-over panel
Скрим `var(--scrim)` + `tk-fade`; панель справа: width 480, `background:var(--surface)`,
`border-left:1px var(--border)`, тень слайд-овера, анимация `tk-slide` 220ms `--ease`.
Хедер 52px: type chip · issueKey · тип · ─── · Delete · Close. Тело — скролл.
Закрытие: клик по скриму, Close, `Esc`. Фокус — в панель (focus trap), при закрытии — назад на
инициатор.

### 4.11 Modal
Скрим + центрирование по горизонтали, `padding-top:11vh`. Панель width 480, radius 15,
`box-shadow:var(--shadow-modal)`, анимация `tk-pop`. Хедер (padding 15 18, нижний бордер) ·
тело (18) · футер (13 18, `background:var(--surface-2)`, верхний бордер, кнопки справа `gap:8`).
`Esc` — отмена, `Cmd/Ctrl+Enter` — подтвердить. Клик по скриму закрывает, клик внутри — нет.

### 4.12 Popover (notifications)

### 4.18 Not found / no access screen
Полноэкранный маршрут вне app shell (как логин): центрированная колонка,
`min-height:100vh`, фон `--bg`. Показывается для неизвестного URL (`*`) и когда
загрузка проекта на борде падает с NOT_FOUND / PERMISSION_DENIED (404/403).
Текст **намеренно не различает** «страницы нет» и «нет прав» — не раскрываем
существование чужих проектов.

Третий случай — `/admin` у пользователя, который не `GLOBAL_ADMIN` (§5.1).
Сюда же попадает профиль, который не загрузился вообще: `GET /users/me` упал по
транспортной причине — это не 404 и не 403, но подтвердить админство мы не
можем, а экран даёт выход. Отклонение осознанное, зафиксировано здесь, чтобы
§4.18 продолжал описывать то, для чего экран на самом деле используется.

Пока роль неизвестна, `/admin` рисует **пустую плоскость** `--bg` — ни топбара,
ни скелетона (отклонение от §5.6). Показать шапку и через мгновение заменить её
экраном «не найдено» — та самая «секунда правдоподобного интерфейса», против
которой §4.18 и существует. Для глаза там ничего, для скринридера — визуально
скрытый `role="status"`: `aria-busy` на пустом лендмарке не сообщает ничего.

- **Маскот** — вторая разрешённая иллюстрация после свечения логина:
  расплавившийся 3D-кубик Taska с глазами-крестиками и высунутым языком.
  Сгенерирован владельцем во внешней модели (в исходном PNG первого рендера —
  подписанный C2PA-манифест: `gpt-image`, `trainedAlgorithmicMedia`).
  Ширина бокса 360 (`max-width:78vw`), сама фигура вписана в кадр 3:2 и
  оптически занимает около 260 — размер задаётся по фигуре, не по кадру.
  Декоративный: весь смысл несут заголовок и текст.
  Собственной тени не нужно: лужа с каплями в самой картинке уже сажает
  фигуру на плоскость.
- **Маскот собирается из каналов и следует за `--accent`** (TAS-159). Вместо
  одного запечённого кадра — три слоя в `src/assets`:
  `mascot-notfound-alpha.webp` (силуэт-маска), `-shade` (умножение: белый там,
  где поверхность берёт акцент как есть, темнее там, где форма отворачивается),
  `-light` (экран: чёрный везде, кроме бликов и логотипа). Формула —
  `accent × shade + light`, обрезано по alpha; собирается компонентом
  `TaskaMascot` внутри `isolation:isolate`, иначе blend-режимы достанут до
  страницы под маскотом. У каждого канала своя прозрачность, поэтому маской
  накрыт только слой заливки.
  Прежнее ограничение — «фиолетовый запечён в пиксели, смена акцента требует
  перерисовки» — этим снято: цвет теперь токен, как везде (§2.1).
  Исходники каналов — `docs/design/mascot-channels/` (PNG 1536×1024, ~2.7 МБ
  на оба маскота); без них каналы не пересобрать. Исходный рендер первой версии
  с манифестом остаётся в `docs/design/mascot-not-found-source.png` как запись
  происхождения персонажа.
- **Заголовок** «Page not found» — page title (22/700, `--fg`, -0.025em), `h1`.
- **Текст** 13/400 `--fg-2`, `max-width:340`, центр, `text-wrap:pretty`;
  покрывает оба случая одной фразой.
- **Действие** — primary «Go to projects» (§4.1): семантически ссылка на
  `/projects`, стилизованная как `.primary-button`.
- Вход — `tk-pop var(--dur-enter)` (reduced-motion схлопывает через токены §3),
  0%-кадр читаем. Маскот въезжает вместе с блоком, собственной анимации у него
  нет.
- **Загрузка проекта не ретраится на 404/403.** Глобальный `retry: 1` (react-query,
  `retryDelay` 1000мс) относится к 404 как к транзиентной ошибке, и борд успевал
  показать секунду правдоподобного чужого хрома — топбар, фильтр-бар, колонки —
  ровно перед экраном, который существует, чтобы этого не показывать.
  Project-scoped запросы борда отсеивают такие ошибки предикатом `retry`;
  замерено: 1044мс → 36мс.

### 4.19 Заглушка раздела в разработке
Экран раздела, который уже есть в навигации, но ещё не имеет ручек (§5.8).
Живёт **внутри** admin-shell: рельс, топбар и заголовок раздела на месте —
пустой здесь контент, а не страница. Этим он отличается от §4.18, который
именно что заменяет собой всё.

- **Маскот** — третья и последняя разрешённая иллюстрация (§1): тот же кубик
  Taska, что на Not found, но в строительной каске, с ограждением, мигалкой и
  чертежом. Собирается тем же `TaskaMascot` из тех же трёх каналов
  (`mascot-building-alpha|shade|light.webp`) и так же следует за `--accent`.
  Ширина бокса 256 (`max-width:70vw`), фигура оптически занимает около 220.
  Декоративный: смысл несут заголовок и текст.
- **Четвёртый слой — `mascot-building-static.webp`**, поверх собранного, без
  blend-режима: мигалка, ластик и грифель карандаша. Причина не в семантике
  цвета — это декоративная иллюстрация, её мигалка ничего в продукте не
  сигнализирует, и ссылаться здесь на «предупреждающий сигнал» значило бы дать
  будущему читателю основание завести оранжевый элемент в настоящем UI. Причина
  в идентичности предметов: янтарная мигалка, розовый ластик и деревянный
  грифель — это то, чем эти предметы являются, а акцент красит материал кубика.
  Поэтому все три лежат в одном слое, и поэтому у маскота Not found такого слоя
  нет: в нём нечему оставаться нетонированным.
- Не анимируется: мигалка на картинке уже горит, а мигающий элемент в служебном
  разделе — ровно то, чего §1 просит избегать.
- **Заголовок** 15/600 `--fg`, имя раздела в предложении: «Events — раздел в
  разработке».
- **Текст** 12.5/400 `--fg-2`, `max-width:360`, `text-wrap:pretty`: одна фраза
  о том, что раздел появится, и **ключ истории, которая его откроет** — читатель
  этого экрана единственный, кому ключ полезен, и он же обычно тот, кто может
  спросить о статусе.
- Ключ истории — ссылка на Jira, `--fg-2` → `--accent` на hover, внешняя
  (`target="_blank"`, `rel="noreferrer"`).
- Никаких кнопок. Заглушка ничего не предлагает сделать: единственное осмысленное
  действие — уйти в другой раздел, а он уже в рельсе слева.
- Вход — `tk-pop var(--dur-enter)`, 0%-кадр читаем (§7).

Компонент один на все пустые разделы; различаются только имя раздела и ключ.
Когда раздел получает ручки, заглушка снимается вместе с записью в §5.8, а не
остаётся под флагом.

## 5. Patterns

### 5.1 App shell и маршруты
Фиксированный топбар (+ фильтр-бар на доске) → прокручиваемая область контента.
`height:100vh; display:flex; flex-direction:column; overflow:hidden`; скроллит только контент.

| Экран | Route | Доступ |
| --- | --- | --- |
| Login / Accept invite | `/login`, `/invite?token=…` | публичный |
| Projects | `/projects` | по сессии |
| Board | `/projects/:projectId/board` | по сессии |
| Issue card | `/projects/:projectId/issues/:issueId` | по сессии |
| Admin | `/admin/*` (§5.8) | по сессии **и** `globalRole = GLOBAL_ADMIN`; иначе §4.18 |
| Not found / no access | `*` (fallback); также борд при NOT_FOUND / PERMISSION_DENIED (§4.18) | публичный |
| Notifications | поповер, без маршрута | — |

Issue card — **slide-over поверх доски**, а не отдельная страница: URL меняется,
доска остаётся под затемнением, закрытие панели возвращает на `…/board`.
Ручки для каждого экрана — в контракте `docs/contract/openapi.yml`.

**Приватные маршруты.** `/projects`, `…/board`, `…/issues/:issueId` и `/admin`
открываются только с сессией: гвард спрашивает у `TaskaApi` синхронное «есть ли
у клиента учётные данные» и без них отдаёт `/login`, запомнив запрошенный адрес —
после входа пользователь возвращается именно туда, а не в общий список проектов.
У `/admin` поверх сессии есть вторая проверка — `globalRole = GLOBAL_ADMIN`, и
она уже не про гвард, а про то, что рисует сам экран (§4.18).
Голый заход на `/` — это редирект в `/projects`, поэтому до гварда он доходит
уже как эта страница и после входа возвращается в неё же; отдельного случая ему
не нужно. Ни в одном из этих случаев форма ничего дополнительно не объясняет:
форма входа после клика по закрытой ссылке объясняет себя сама. Зеркальное
правило: посетителя, у которого сессия уже есть, `/login` отправляет в
`/projects`. `/invite` остаётся публичным намеренно — инвайт принимают и будучи
залогиненным под другим аккаунтом; `*` (Page not found) тоже вне гварда:
несуществующий адрес должен отвечать «страницы нет», а не формой входа, которая
намекала бы, что страница существует и просто закрыта (§4.18). Наличие сессии —
не право доступа: сервер остаётся авторитетом (§5.7).

**Смерть сессии.** 401, который не удалось починить refresh-ом, обрабатывается в
одном месте, а не каждым экраном по-своему: `App` подписан на сигнал от
`TaskaApi`, чистит кэш react-query (ответы принадлежали сессии, которой больше
нет) и возвращает пользователя на `/login` с запомненным адресом страницы, где
это случилось, и с объяснением «Your session expired. Sign in to continue.».
Так как переход происходит без просьбы пользователя, фокус переводится на само
объяснение (§7) — иначе о нём не узнает ни скринридер, ни клавиатура. Осознанный
выход из аккаунта объяснения не показывает: это не истечение сессии.

### 5.2 Board layout
Полотно `flex; gap:14; overflow-x:auto; align-items:flex-start`, колонки во всю высоту,
внутренний скролл — у списка карточек, не у полотна.

### 5.3 Drag & drop
- Источник — карточка задачи; цель — колонка (в MVP порядок внутри колонки не сохраняем).
- `dragstart` → запомнить `issueId`, `effectAllowed='move'`; `dragover` на колонке →
  `preventDefault()` + подсветка; `drop` → переход статуса; `dragend` → сбросить состояние.
- Обновление **оптимистичное**: карточка сразу в новой колонке, затем `POST …/transitions`;
  при ошибке — вернуть назад + тост.
- Клавиатурная альтернатива обязательна: transition-кнопки в карточке задачи.
- Библиотека по умолчанию — `@dnd-kit/core`.

### 5.4 Filtering
Фильтры комбинируются по AND: `type` + `assignee` + текстовый `q` (по `summary` и `issueKey`,
case-insensitive). «Clear» показывается только когда что-то активно. Счётчик «X of Y» —
всегда. Серверные фильтры (`status`, `assigneeId`) отдавать в `GET /issues`, поиск —
локально по загруженной странице (пока нет серверного).

### 5.5 Inline editing
Заголовок и описание задачи редактируются на месте (без «режима правки»): изменение → локальный
стейт сразу → `PATCH` с debounce 600ms → в ленте активности появляется событие. Ошибка → откат
значения + тост.

### 5.6 Empty / loading / error
- **Loading:** скелетоны формой конечного элемента (карточки колонок, строки списка), фон
  `--surface-2`, пульсация `opacity .35→1`. Спиннеров в контенте не использовать.
- **Empty:** одна строка 11.5–12px `--fg-3` в пунктирной рамке (колонка) или короткий текст +
  primary-действие (список проектов).
- **Error:** тост снизу справа: `background:var(--surface); border:1px var(--border);
  radius:11; box-shadow:var(--shadow-pop)`, текст 12.5px, акцент-полоса/иконка `--danger`.
  Показывать `error.message`, `error.requestId` — мелким `--fg-3` (копируемым).

> **Пробел (TAS-140).** Тост-компонента в коде нет. Ошибки показываются только инлайном
> (`.form-error` на формах логина и создания задачи), а `requestId` не доходит до
> пользователя вообще. Это значит, что откаты оптимистичных мутаций (§5.3, §5.5) сейчас
> происходят молча: карточка возвращается в исходную колонку без единого объяснения.
> Требование выше — правильное, поэтому оно оставлено как есть, а не подогнано под код.
> Спецификация тоста — контракт для будущей реализации, а не описание текущего состояния.

### 5.7 Permissions
Роль берём из `GET /projects/{id}/membership`. `VIEWER` — только чтение: скрывать «New»,
transition-кнопки, Delete, drag (`draggable=false`), инлайн-редактирование (readOnly),
composer комментариев.
Не полагаться только на скрытие — сервер всё равно проверяет.

Комментарии гейтятся **двумя** правилами, не одним: создание — по роли
(`ADMIN`/`MEMBER`), редактирование и удаление — по авторству (`comment.authorUserId ===
currentUser.id`). Роль `ADMIN` не даёт права править чужой комментарий.

> **Внимание при проверке прав.** В режиме `hybrid` с
> `VITE_TASKA_ASSUME_PROJECT_ADMIN=true` роль синтезируется на клиенте и всегда `ADMIN`
> (см. §6, «Режимы API» и `docs/ai/API-DIVERGENCE.md`). Прошедшая в этом режиме проверка
> ролевого гейтинга не доказывает ничего: `VIEWER` в нём просто недостижим.

### 5.8 Раздел администрирования
`/admin` — не экран, а собственная область с разделами. Она остаётся внутри
общего app shell (§5.1): топбар тот же, меняется только тело.

**Разделы и маршруты.**

| Раздел | Route | Состояние |
| --- | --- | --- |
| Data | `/admin/data/:service?/:table?` | работает; строка по ключу — `…/:table/:id` (TAS-161) |
| Events | `/admin/events` | заглушка §4.19 до TAS-105 |
| Users | `/admin/users` | заглушка §4.19 до TAS-107 / TAS-108 |
| Audit | `/admin/audit` | заглушка §4.19 до TAS-160 |

`/admin` без хвоста редиректит в `/admin/data`. Разделы рисуются **все**, включая
незаполненные: структура раздела — это тоже информация, и админ, который видит
Audit заглушкой, знает о нём больше, чем админ, который не видит ничего.
Гейт `globalRole = GLOBAL_ADMIN` стоит один раз на всей области (§4.18, §5.7);
сервер остаётся авторитетом на каждой ручке.

**Состояние — в URL, не в React.** Выбранные сервис, таблица и строка живут в
маршруте, страница и фильтр — в query. Админская работа состоит из «посмотри вот
на это»: ссылка на конкретную таблицу должна открываться у другого админа и
переживать перезагрузку. Это же снимает старое поведение, где первая таблица
каталога подставлялась молча, — теперь подстановка видна в адресе.

**Шапка области.** Над телом раздела: крошка «Administration ›» 11.5/550
`--fg-2` и следом имя раздела (22/700 `--fg`). Обе части — **внутри одного
`h1`**: причина, по которой крошка существует, ровно так же верна в дереве
доступности, а соседний `<p>` оставил бы заголовок с именем «Data». Область
называет себя, а не только текущий раздел: «Data» без контекста читается как
ещё один экран продукта.

Справа — маркер `read-only`: 10.5px моно `--fg-2` (не `--fg-3`: тот даёт 2.8:1
на этой плоскости, а это утверждение, а не украшение), рамка `1px --border`,
`radius:6`, `padding:2 7`. Он не украшение и не статус запроса. **Свойство
раздела, а не области:** сегодня читают все четыре, но TAS-106 приносит retry в
Events, а TAS-107/108 — блокировку в Users, и каждый снимет маркер со своего
раздела сам. У разделов-заглушек маркера нет вовсе — раздел, который ничего не
делает, не может осмысленно заявлять, что только читает.

**Рельс разделов.** Слева, ширина 168, фон `--surface`, правая граница
`1px --border`. Пункт: иконка 15 + текст 12/600, `padding:6 9`, `radius:8`,
в покое `--fg-2`, hover — `--surface-2` + `--fg`, активный — `--surface-2` +
`--fg` + `aria-current="page"`. Внизу, за разделителем, выход в `/projects`
(`--fg-3`). Отдельной кнопки «Back to projects» под контентом больше нет: выход
из области принадлежит области, а не последнему её экрану. Логотип в шапке
(§4.13) ведёт туда же и рельсе не противоречит: это выход из **оболочки**,
одинаковый на всех экранах с сессией, тогда как выход в рельсе принадлежит
разделу и стоит там, где читатель уже выбирает раздел. На ширине < 900 они
видны одновременно, и это приемлемо — дублируется цель, а не элемент
управления. На ширине < 900
рельс схлопывается в горизонтальную полосу над контентом.

**Data: колонка каталога.** Вторая колонка, ширина 200, фон `--bg`: поле поиска
(§4.14, 26px) и под ним список, сгруппированный по сервису — заголовок группы
10.5px `--fg-3` uppercase, пункт таблицы 11.5px моно, активный — `--surface-2` +
`--fg`. Плоский ряд чипов, который был здесь до TAS-159, держал четыре таблицы и
ломался на десяти; шесть сервисных БД дают три-четыре десятка. Поиск фильтрует
по имени таблицы и сервиса, пустой результат — строка «Nothing matches» 11.5px
`--fg-3`.

**Data: таблица.** Плотность выше продуктовой — это чтение сырых строк, а не
работа с задачами:
- строка 30, `padding:6 10`, базово 11.5 UI-шрифтом;
- моно (§2.3, 11.5/500, `tabular-nums`) — **только** для значений, которые
  сравнивают глазами по вертикали: id, временные метки, числа, JSON, имена
  сервисов и таблиц. `email`, `display_name` и прочая проза остаются UI-шрифтом.
  Моно на всей таблице было бы «атмосферой», а её `docs/ai/REFERENCE-LOCK.md`
  запрещает прямым текстом; выравнивание колонки идентификаторов — это работа,
  а не атмосфера, и различие проходит ровно по типу колонки из каталога;
- шапка `position:sticky; top:0`, фон `--surface-2`, текст 11/600 `--fg-2`;
- колонка primary key примораживается слева (`position:sticky; left:0`) с
  правой границей `1px --border` — при горизонтальном скролле строка обязана
  оставаться опознаваемой;
- **значение primary key длиннее 12 символов обрезается до первых 8** и несёт
  полное значение в `title` и в accessible-имени, а по клику копируется целиком.
  Подтверждение — двухсекундная подсветка самого ключа плюс визуально скрытый
  live-region, а **не** надпись рядом, как у Request ID: там подпись ничего не
  двигает, а здесь «Copied» расширяла примороженную колонку на 45px и дважды
  сдвигала всю таблицу, ради которой колонку и примораживали. Отказ буфера
  говорит «Couldn't copy» — молчание неотличимо от мёртвой кнопки.
  Примороженная колонка имеет смысл, пока она узкая: полный uuid
  в 36 символов делает её самой широкой в таблице и выталкивает остальные
  колонки за край — ровно та беда, из-за которой раздел и переделывался.
  Короткий ключ (числовой id, короткий код) не трогаем;
- контейнер скролла несёт `tabindex="0"` и `aria-label` (§7): без этого таблица,
  у которой нет сортируемых колонок, не скроллится вбок с клавиатуры в Safari и
  Firefox вообще;
- **sensitive-колонка — это теперь три случая, а не один** (TAS-104). Маскирует
  сервер, и делает это тремя способами, а каталог сообщает только
  `sensitive: true` — какой способ достался колонке, видно исключительно по
  пришедшему значению. Ключа в строке нет (`HIDE`) или значение равно `***`
  (`MASK_FULL`) — иконка замка + `hidden` `--fg-3` в ячейке; до читателя не
  дошло ничего, и это единственное, что замок **в ячейке** отныне означает.
  Значение со звёздочками (`MASK_PARTIAL`) печатается как пришло: `n****a@mail.ru`
  отвечает на вопрос «чей это ящик», а замок поверх него не отвечает ни на что —
  ровно ради этого ответа частичную маску у бэкенда и просили;
- **замок никуда не делся, а переехал в шапку колонки** — и в метку поля на
  карточке. Он свойство колонки, а не ячейки, поэтому говорится один раз, а не в
  каждой строке; без него `a*****ample.com` читался бы как хранимое значение. В
  шапке он берёт `--fg-2` по наследству, а не `--fg-3`: на `--surface-2` в
  светлой теме `--fg-3` даёт 2.76:1 при пороге §7 в 3:1, а на колонке с
  частичной маской этот значок — единственное, что отличает звёздочки от данных,
  и служебным цветом он поэтому не красится;
- **«никогда длину значения» остаётся правилом, но адресовано оно теперь
  серверу.** Оно писалось, когда клиент был единственным, что стоит между
  читателем и значением. Сейчас решает сервер, и для `MASK_PARTIAL` он длину уже
  раскрыл — она в теле ответа, в кэше react-query и в devtools независимо от
  того, что нарисовано на экране. Клиенту запрещено раскрывать **больше**
  сервера: дорисовывать длину, восстанавливать маску, показывать `***` как
  данные;
- fail closed теперь в обе стороны: правило по-прежнему из каталога и при
  отсутствии записи в каталоге таблица не показывается вовсе, а вдобавок
  значение sensitive-колонки печатается, только если несёт след маскировки —
  звёздочку. Колонка, пришедшая открытым текстом вопреки каталогу, прячется:
  каталог сказал, что там секрет, а хеш, попавший на экран, обратно не вернуть;
- `null` — `—` `--fg-3`. Прочерк на месте пустого значения — это служебный
  знак, а не данные, и по §1 он не имеет права весить столько же, сколько
  содержимое соседней строки;
- строка кликабельна и ведёт на `…/:id` — карточку строки. Три условия, все
  обязательные: каталог назвал primary key, его тип — `uuid`, и колонка ключа
  не помечена sensitive. Первые два — про гейтвей, который принимает `id`
  именно как UUID, поэтому строку с числовым или текстовым ключом адресовать
  нечем. Третье — про сам адрес: ключ входит в URL, а с ним в адресную строку,
  в доступное имя ссылки и в историю браузера, так что ссылка на строку с
  секретным ключом напечатала бы ровно то значение, которое таблица только что
  отказалась показать. Не выполнено любое — строка не кликабельна и не
  притворяется: ссылка, которая гарантированно приводит к отказу или к утечке,
  хуже её отсутствия;
- **клавиатурный путь — отдельная ссылка в последней ячейке строки**, а не сама
  строка: `<tr>` не может быть контролом, и «кликабельная строка» без этого
  означала бы раздел, проходимый только мышью. Цель не меньше 28×28 (§7),
  фокус — `focus-visible` с отступом 2px, и **строка в фокусе подсвечивается
  так же, как при наведении**. Последнее не косметика: на широкой таблице
  ссылка уезжает за правый край контейнера скролла, и без подсветки строки
  клавиатурный читатель видит кольцо, но не видит, к какой строке оно
  относится.

**Data: карточка строки.** `…/:table/:id` — не модалка, а тело раздела вместо
таблицы: адрес обязан открываться прямой ссылкой у другого админа, а модалка,
восстановленная из URL, приезжает поверх пустоты. Рельс и колонка каталога
остаются на месте — читатель не вышел из таблицы, он смотрит одну её строку.

- шапка карточки: имя таблицы 12/600 и под ним значение ключа целиком,
  11.5 моно с копированием по клику (подтверждение — как в §5.8 для ключа в
  таблице). Здесь ключ показывается **полностью**: обрезка до 8 символов
  существует ради ширины примороженной колонки, а карточка — то самое место,
  куда идут за полным значением;
- поля — список пар: имя колонки 11/600 `--fg-2` слева колонкой ширины 200,
  значение справа. Значение подчиняется тому же правилу шрифта, что и ячейка
  таблицы: моно с `tabular-nums` для id, времени, чисел и JSON, UI-шрифт для
  прозы. Значение не обрезается и переносится — на карточке нет соседних
  колонок, которые обрезка защищала бы;
- `null` — `—` `--fg-3`, как в таблице; sensitive-колонка — те же три случая и
  то же fail closed, что в таблице, но замок здесь **только** в метке поля:
  метка и значение стоят одно под другим, и два одинаковых замка в 38 пикселях
  друг от друга читаются как заикание, а не как два разных утверждения. Значение
  несёт один курсивный `hidden` `--fg-3`. В таблице замок в ячейке остаётся —
  там метка колонки далеко, в примороженной шапке;
- ширина карточки ограничена 860. Метка занимает 200, самое длинное значение —
  около 300, и без ограничения на 1920 разделители тянутся через тысячу
  пустых пикселей. Ограничение читаемой полосы — общее правило продукта (§2.7),
  а не исключение для этого экрана;
- имя таблицы и ключ повторяются: в ссылке назад и в шапке, в шапке и в поле
  `id`. Это сознательно. Шапка — адрес строки, список полей — сама строка
  целиком, и выбросить из него колонку ключа значило бы, что список врёт о том,
  из чего строка состоит. Цена — два повтора; альтернатива — список, про
  который надо помнить, что одна колонка из него изъята;
- назад — ссылка «‹ `service.table`» над карточкой. Переход из строки уносит
  query таблицы (`page`, `sort`, `filter`) в адрес карточки, и ссылка назад
  возвращает ровно ту страницу и тот фильтр, из которых читатель пришёл.
  Без этого возврат из строки на 7-й странице отправлял бы на первую.
  Доступное имя — «Back to `service.table`», а не одно имя таблицы: шеврон
  `aria-hidden`, и без подписи ссылка звучит ровно как заголовок карточки
  тридцатью пикселями ниже — два одинаковых слова, ни одно из которых не
  сказало, что это выход;
- строки, которой нет, сервер отвечает 404. Это не §4.18: адрес раздела верен,
  отсутствует конкретная строка — «No row with this key in `service.table`»
  внутри карточки, рельс и каталог остаются рабочими.

**Data: фильтр.** Кнопка-чип «+ Filter» открывает поповер (§4.12) с тремя полями
column / match / value. Применённый фильтр показывается чипом
`column match value` с крестиком; кнопка «Clear» отдельной строкой не нужна.
Форма из трёх подписанных селектов в ряд, которая была здесь раньше, занимала
полосу шириной с экран ради одного фильтра — а больше одного контракт и не даёт.

Чип обрезается по ширине, и тогда на нём действует то же правило, что и на
ключе в таблице: полное значение обязано остаться и в `title`, и в доступном
имени. Обрезка, после которой значение негде прочитать целиком, — это потеря
данных, а не экономия места. Фильтр с пустым значением не применяется и чипа не
создаёт: чип, который читается как применённый, над нефильтрованной таблицей —
худший из возможных ответов, и от него не спасает то, что запрос ушёл честным.

Набор операторов зависит от типа колонки из каталога, и это не удобство, а
единственный способ не отправить запрос, который сервер отвергнет: гейтвей
проверяет совместимость сам и отвечает 400. `contains` — только текстовые
колонки, `from`/`to` — временные и числовые, `is` — любые. Оператор, потерявший
смысл при смене колонки, сбрасывается в `is`, а не остаётся выбранным в селекте,
где его опции уже нет. Когда тип колонки допускает **единственный** оператор —
а это частый случай, `uuid`, `inet` и `boolean` все дают только `is` — Match
рисуется статическим текстом 11.5 `--fg-2` на месте селекта, а не селектом с
одним пунктом: выпадающий список, который не может ничего изменить, притворяется
выбором.

Значение тоже ограничивается типом, и по той же причине: сервер разбирает его
типизированно и отвечает 400. Числовая колонка получает числовое поле, булева —
выбор `true`/`false`, временная — датапикер. Свободное текстовое поле остаётся
только там, где сервер и правда принимает произвольную строку.

**Время в этом разделе — UTC, и поле обязано это сказать.** Датапикер читается
как UTC, а не как локальные часы, и подписан «UTC» — потому что UTC на проводе,
а не потому, что так сегодня выглядит колонка. Разница существенная: таблица
печатает то, что отдал сервер, и если какой-нибудь сервис однажды вернёт
временную колонку с другим смещением, обоснование «в таблице же `Z`» исчезнет, а
пикер молча станет неверным ровно тем способом, которым только что перестал.
Колонка с не-`Z` смещением — это изменение контракта, которое поднимают, а не
деталь отображения, которую всасывают.

Без подписи админ, глядя на колонку с `08:00:00Z`, вводит 08:00 и получает
фильтр на три часа раньше — цифры, которые он набрал, и цифры, по которым идёт
отбор, разъезжаются молча. На проводе — полный ISO-8601
со смещением и **без миллисекунд** (`2026-01-01T00:00:00Z`): сервер парсит
строго, `2026-01-01` и `2026-01-01T00:00` — уже 400, а `.000` ничего не
добавляет и съедает четверть ширины чипа. Формат — работа формы, а не то, что
админ обязан помнить.

**Пагинация** — в футере таблицы, `position:sticky; bottom:0`, фон `--surface-2`,
не отдельным блоком под ней. Футер показывается **всегда**, даже когда страница
одна: «Page 1 of 1» — это ответ на вопрос «я вижу всё?», а таблица, у которой
футер то есть, то нет, каждый раз меняет высоту рабочей области. Кнопки при
одной странице просто выключены.

**Ошибки.** Четыре случая различаются словами, а не одним текстом: отказ
сервера (403/404), **отвергнутый запрос (4xx)**, ошибка сервера (5xx) и
недоступность. Четвёртый случай — это «мы не дозвонились», и всё, что попадает
в него по недосмотру, читается как авария инфраструктуры: раздел уже один раз
называл так пятисотку, и с приходом типизированной валидации на гейтвее
четырёхсотка стала штатным ответом на плохой ввод, а не редкостью. Рядом с
заголовком печатается текст самого сервера — он называет колонку и то, что с
ней не так, и это единственная часть, которая говорит читателю, что именно
исправить. `X-Request-Id` показывается только в этой области — здесь он у
единственного читателя, который пойдёт с ним в лог гейтвея — и **копируется по
клику** (иконка копирования 14, подтверждение «Copied» 11px `--fg-3` на 2с).

**Область desktop-first, и это сказано вслух.** Раздел читают с рабочей машины;
на телефоне он остаётся достижимым, но не оптимизированным: рельс сворачивается
в горизонтальную полосу (<900), каталог уезжает над таблицей (<720), и цели
касания там 26–29px против 44 из §7. Это осознанная граница, а не забытая
работа. Что действительно нужно сделать при первой же необходимости работать с
телефона — превратить каталог в раскрывающийся список с триггером из имени
таблицы, чтобы строки получали весь экран; пока этого нет, нижний край списка
закрыт маской-затуханием, и это заплатка, а не решение.

> **Пробел (TAS-156).** Живой гейтвей отдаёт 500 на `GET /readonly/{service}/{table}`
> для любой таблицы, поэтому раздел Data проверяется только против мока.
> Формулировка про «фолт на сервере» в §5.8 написана по живому ответу и остаётся
> верной; всё остальное в этом разделе доказано только мок-режимом.

## 6. Data & state conventions

### Enums (ровно как в REST-контракте, без proto-префиксов)
```ts
type UserStatus    = 'INVITED' | 'ACTIVE' | 'BLOCKED';
type ProjectRole   = 'ADMIN' | 'MEMBER' | 'VIEWER';
type IssueType     = 'TASK' | 'BUG' | 'STORY';
type IssuePriority = 'LOW' | 'MEDIUM' | 'HIGH';
type IssueStatus   = 'TODO' | 'IN_PROGRESS' | 'DONE';
type IssueEventType =
  | 'CREATED' | 'TRANSITIONED' | 'ASSIGNED' | 'PRIORITY' | 'UPDATED' | 'DELETED'
  | 'COMMENT_CREATED' | 'COMMENT_UPDATED' | 'COMMENT_DELETED';
```
Комментарий (`IssueComment`): `id`, `issueId`, `projectId`, `authorUserId`, `body`,
`createdAt`, `updatedAt` (`null`, пока не редактировали — по нему и рисуется пометка
«edited»), `version`.
Отображаемые названия статусов: `TODO → "To Do"`, `IN_PROGRESS → "In Progress"`, `DONE → "Done"`.
Названия типов: `Task` / `Bug` / `Story`. Приоритеты: `Low` / `Medium` / `High`
(в узких сегментах — `Med`).

### Формат данных
- Идентификаторы — UUID-строки; в UI показываем `issueKey` (`ABC-123`), а не id.
- Время — ISO-8601 UTC; в UI: на карточке `MMM d` («Jun 25»), в мете/ленте `MMM d, HH:mm` (24ч),
  в уведомлениях — относительное («2h ago», «Yesterday»).
- Enum-значения не локализуем в данных, только при выводе.

### State layering
| Слой | Что | Где |
| --- | --- | --- |
| session | currentUser, accessToken/refresh | auth-контекст + `GET /users/me` |
| route | projectId, issueId | URL (§7 handoff README) |
| server | projects, membership, workflow, issues, issue+history, comments, notifications | react-query, мутации оптимистичные + инвалидация |
| board ui | `{ q, type, assignee }`, dragIssueId, dragOverStatus | локальный стейт экрана |
| app ui | theme, notifOpen, creating, draft, editingCommentId | локальный стейт / контекст, theme persist |

Правило: **никогда** не дублировать серверные данные в локальном стейте — только id и ui-флаги.

Исключение — черновики инлайн-редактирования (summary/description задачи, тело
комментария). Их приходится держать локально, потому что пользователь печатает быстрее,
чем отвечает сеть. Пересев с серверного значения делается **на рендере**, а не в
`useEffect`: эффект стоит лишний проход рендера на каждом рефетче, а сброс через `key`
сбивает фокус посреди набора текста. Для строки комментария `key` наоборот уместен — там
переключение в режим правки и должно пересоздавать черновик.

### Режимы API
`VITE_TASKA_API_MODE`: `mock` (полностью в памяти) · `rest` (только гейтвей) ·
`hybrid` (по умолчанию). Переключение — в `src/api/client.ts`, общий контракт —
`src/api/TaskaApi.ts`.

`hybrid` существует только потому, что `TAS-137` ещё не задеплоен: membership и список
участников синтезируются на клиенте из `GET /projects/{id}` и `GET /users/me`. Следствие
для UI — **в проекте виден ровно один участник**, текущий пользователь, независимо от
того, сколько их на самом деле. Фильтр по исполнителю и чипы assignee в этом режиме не
могут предложить никого другого.

Полный разбор — `docs/ai/API-DIVERGENCE.md`. Когда `TAS-137` выедет, `HybridTaskaApi`
удаляется целиком, а режим по умолчанию становится `rest`.

## 7. Accessibility

> **Записанные разрывы с кодом (TAS-142), найдены ревью art-director 2026-08-03.**
> Требования ниже остаются контрактом; здесь — честный список того, что им пока
> не соответствует, чтобы документ не читался как описание текущего состояния:
> - `Esc` закрывает только меню профиля. Slide-over, модалка создания и поповер
>   уведомлений его игнорируют; поповер не закрывается и по клику вне.
> - У slide-over нет `role="dialog"`/`aria-modal`, focus trap и возврата фокуса —
>   за открытой панелью в tab-порядке остаются десятки элементов. У модалки роль
>   есть, trap нет.
> - `:focus-visible` реализован только в меню профиля; остальной продукт — на
>   дефолтном браузерном outline вместо `2px var(--accent)`.
> - Триггер уведомлений без `aria-expanded` и счётчика в имени; фильтр
>   исполнителя без `aria-pressed`; непрочитанность — только цветом.
> - Контрасты ниже порогов: status-pill по рецепту §4.5 — 1.91:1 для `TODO`;
>   неактивные сегмент-табы (`--fg-3` вместо `--fg-2` из §4.2) — 2.76:1.
> - Touch-таргеты на 390px меньше 44×44 (колоночный «+» — 22px; здесь §7
>   противоречит §4.9 — решить в доке при закрытии TAS-142).

- Контраст: основной текст ≥ 7:1, вторичный ≥ 4.5:1, `--fg-3` использовать только для
  некритичной меты (≥ 3:1). Проверять оба режима.
- **Как мерить контраст на подложке из `color-mix(… , transparent)`.** Считать по
  фактически отрисованным пикселям: взять вычисленное браузером
  `oklab(… / α)` и скомпоновать его над цепочкой родителей. Не «подмешивать»
  `transparent` к координатам вручную: CSS смешивает с `transparent`
  **premultiplied**, поэтому оттенок сохраняется целиком и падает только альфа,
  а ручное смешение уводит цвет к чёрному и меряет текст против плоскости
  *под* тинтом, а не против самого тинта.
  Ошибка не случайна и потому опасна: она **занижает на светлой теме (−12%) и
  завышает на тёмной (+11%)**. На 12% тинте это безобидно, но на рецепте
  статус-пилюли из §4.5 (16% тинт, семантический цвет текста на тёмной теме)
  тот же метод превратит непроходной коэффициент в проходной.
  Установлено `art-director` 2026-08-12 при сверке двух расчётов одного и того
  же баннера, разошедшихся на 1.8 пункта.
- Цвет никогда не единственный носитель смысла: тип — цвет + форма чипа + текст; приоритет —
  количество баров + `title`; статус — колонка + подпись.
- Focus-visible на всём интерактивном: `outline:2px solid var(--accent); outline-offset:2px`.
- Slide-over и модалка: `role="dialog"`, `aria-modal="true"`, focus trap, `Esc` закрывает,
  возврат фокуса на триггер.
- Поповер уведомлений: `aria-expanded` на триггере, счётчик непрочитанных в `aria-label`.
- Иконки-кнопки без текста — обязателен `aria-label`.
- Drag & drop дублируется кнопками переходов (клавиатурный путь).
- Мин. область нажатия 28×28 (плотный тулбар) / 32×32 (обычные), на тач-макетах — 44×44.
- Уважать `prefers-reduced-motion`.

## 8. Code conventions for UI

### Фактическая структура

Раздел описывает то, что есть в репозитории, а не то, к чему стоило бы прийти.
Если появляется новый файл — он встаёт в одну из этих папок.

```
src/
  screens/      App, LoginScreen, ProjectsScreen, BoardScreen — экраны и их состояние
  components/   переиспользуемые куски UI: Avatar, Modal, ThemeToggle,
                UserProfileMenu, TaskaLogo, IssueBits (type-chip, priority-bars)
  api/          TaskaApi (контракт) + mock/ · rest/ · HybridTaskaApi + client.ts
  domain/       types.ts — enum'ы и модели ровно по REST-контракту
  hooks/        useTheme
  lib/          format.ts — форматирование дат и семантические константы §2.2
  test/         setup.ts для vitest
  styles.css    один глобальный файл со всеми классами
```

Стили — **один глобальный `src/styles.css`** с плоскими именами классов
(`.issue-card`, `.comment-item`, `.board-column`). Не CSS Modules, не Tailwind,
не styled-components. Токены §2 объявлены на `:root` там же.

**Известный долг.** `BoardScreen.tsx` — около 1200 строк: доска, фильтр-бар,
slide-over задачи, тред комментариев, модалка создания и поповер уведомлений живут
в одном файле. Разносить по одному компоненту в файл имеет смысл при следующей
крупной правке доски; специально под это отдельную задачу пока не заводили.
Записано как долг, а не выдано за архитектуру.

- **Один компонент — один файл** для всего нового кода; имя файла = имя компонента.
- **Токены только через переменные.** Хардкод hex в компонентах запрещён, кроме семантических
  констант из §2.2 — они объявлены в одном месте, `src/lib/format.ts`
  (`statusColors`, `typeMeta`, `priorityMeta`).
- Тема — атрибут `data-theme` на `<html>`; не использовать классы `.dark` вперемешку с media-query.
- Не создавать вариант компонента ради одного отличия — прокидывать проп (`size`, `tone`, `variant`).
- Иконки — один набор (`lucide-react` или локальные inline-SVG), `stroke-width` 1.2–1.7,
  `currentColor`, размеры кратны шагу из §2.7. Не смешивать наборы.
- Списки: `key` = доменный id (`issue.id`), не индекс.
- Никаких инлайн-`!important`; специфичность решаем структурой.
- Числа-магии в вёрстке допустимы только из шкал §2.4/2.5/2.7.

## 10. Definition of done для UI-задачи

1. Совпадает с прототипом по токенам §2 (цвета, типографика, отступы, радиусы, тени).
2. Работает в светлой и тёмной теме; контраст проверен в обеих.
3. Есть состояния: loading (скелетон), empty, error (тост с `requestId`), disabled, focus, hover.
4. Клавиатурная доступность: tab-порядок, focus-visible, `Esc` для оверлеев, альтернатива drag'у.
5. Права по роли (`VIEWER` — read-only) учтены в UI.
6. Мутации оптимистичные, с откатом и тостом при ошибке.
7. `prefers-reduced-motion` уважается; entrance-анимации не скрывают контент.
8. Нет хардкод-цветов и магических отступов вне шкал.
